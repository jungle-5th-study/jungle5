# 문서 안내

| 문서 | 답하는 질문 | 결정 번호 |
|---|---|---|
| [prd.md](prd.md) | 무엇을, 왜 만드는가. 권한 표(5.4), 기능별 수용 기준(8절), 출시 시나리오(11절) | D-xx (2.2절) |
| [tsd.md](tsd.md) | 어떻게 만드는가. 데이터 모델, API, 인증·권한, 배포·백업, 테스트. 구현 중 보완 사항(3.2절) | TD-xx (3절) |
| [ui.md](ui.md) | 어떻게 보이는가. 디자인 토큰, 레이아웃, 화면·컴포넌트, 접근성 | UD-xx (2절) |
| [operations.md](operations.md) | 운영 설정, CI/CD, 백업에서 복구 (메인테이너용) | – |

문서 사이의 순서는 PRD → TSD → UI다. TSD는 PRD 결정을, UI는 PRD·TSD 결정을 근거로 삼는다.

## 결정을 기록하는 방법

- 결정마다 번호를 붙여 각 문서의 결정 표에 한 행으로 적는다. 제품은 D-xx, 기술은 TD-xx, 화면은 UD-xx다. 번호는 이어서 붙이고 다시 쓰지 않는다.
- 행에는 결정, 날짜(필요하면), 근거나 영향을 짧게 적는다.
- 결정을 바꿀 때는 옛 행을 지우지 않는다. 옛 내용에 취소선을 긋고 "→ D-xx로 대체"를 남긴 뒤, 새 번호로 행을 추가한다.
- 다른 문서의 결정을 근거로 쓸 때는 번호로 가리킨다 (예: "TD-23 (PRD D-23)").
- 구현하며 정한 작은 처리 방식은 TSD 3.2절 표에 행을 추가한다.
- 문서를 고치면 맨 아래 문서 이력에 한 줄을 남긴다.
- 제품 동작이나 기술 방식을 바꾸는 PR은 코드와 같은 PR에서 결정 행을 고친다 ([CONTRIBUTING](../CONTRIBUTING.md)).
