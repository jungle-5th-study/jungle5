## 1. 제품 요약

**같은 주제를 함께 공부하는 스터디의 주간 진행을 관리하고, 개인과 스터디의 학습 결과를 카테고리별 지식으로 축적하는 소규모 커뮤니티 사이트.**

제품은 두 공간으로 구성한다.

1. **지식 공간:** 스터디 참여 여부와 무관하게 개인이 공부한 내용·자료를 공유한다.
2. **스터디 공간:** 공통 주제와 학습 범위를 정하고, 주 1회 모임을 중심으로 학습·발표·토론을 관리한다.

두 공간을 연결하되 종속시키지 않는다. 스터디에서 작성한 결과 글은 지식 공간에서도 검색되며, 일반 지식 글은 스터디에 연결하지 않아도 작성할 수 있다.

## 2. 요구사항의 확정 수준

### 2.1 사용자에게 확인된 요구

- 카테고리별 지식 공유가 필요하다.
- 스터디 관리 기능이 필요하다.
- 스터디는 같은 책·강의·주제 등 공통 주제를 함께 공부하는 형태다.
- 각자가 별도로 공부한 내용을 공유하는 정보 공간도 필요하다.
- 보통 일주일에 한 번 모여 공부한 것을 공유하고 토론한다.
- 모임 사이에도 관련 내용과 질문을 남길 수 있어야 한다.
- 저비용으로 운영하는 것이 중요하다.

### 2.3 이 문서의 제안·가정

아래 사항은 확정된 사용자 요구가 아니라 MVP 초안이다.

- 초대받은 멤버가 사용하는 단일 커뮤니티를 우선 지원한다.
- 같은 커뮤니티 안에 여러 스터디를 만들 수 있다.
- 초기 글과 스터디는 로그인한 커뮤니티 멤버에게 공개한다.
- 기본 운영 단위는 스프린트 대신 **회차**로 부른다.
- 한 회차는 기본적으로 주간 모임 하나에 대응하지만, 기간과 모임 시각은 수동으로 조정할 수 있다.
- ~~개인 학습 항목, 막힘 표시, 결과물 연결을 MVP에 포함한다.~~ → D-03으로 학습 항목 제외. 결과물은 회차에 글로 직접 연결한다.
- 대용량 파일 업로드 대신 Markdown과 외부 링크를 사용한다.
- 호스팅비 최소화를 목표로 하되 공급자와 요금제는 기술 설계에서 별도 확정한다.

## 3. 문제 정의와 제품 원칙

### 3.1 해결할 문제 가설

다음은 실제 운영에서 확인해야 할 문제 가설이다.

- 채팅으로 공유한 자료와 질문이 시간이 지나면 다시 찾기 어렵다.
- 이번 주 학습 범위·모임 일정·준비할 내용이 여러 곳에 흩어질 수 있다.
- 모임에서 나온 질문과 결론이 다음 회차로 이어지지 않을 수 있다.
- 개인 학습 결과가 해당 스터디 안에만 남아 다른 멤버가 발견하기 어렵다.

### 3.2 제품 원칙

- **진행은 스터디에서, 재사용은 지식 공간에서.**
- 같은 글을 두 번 쓰게 하지 않는다.
- 관리 입력보다 학습과 토론에 시간을 쓰게 한다.
- 글 작성량·학습 시간·완료율로 사람을 줄 세우지 않는다.
- **대화는 Discord에서, 남길 것만 사이트에.** 사이트는 Discord를 대체하지 않는다.
- 개인 진도 관리·증빙을 요구하지 않는다. 회차에 남는 것은 연결된 글과 공동 기록뿐이다.

## 4. 목표와 비목표

### 4.1 MVP 목표

- 멤버가 카테고리별 지식을 작성하고 다시 찾을 수 있다.
- 스터디 멤버가 회차별 공통 학습 범위와 모임 일정을 안내할 수 있다.
- 멤버가 모임 사이 학습 결과를 글로 남길 수 있다.
- 모임에서 회차의 학습 결과와 지난 회차의 남은 질문을 한 화면에서 확인할 수 있다.
- 모임 기록과 다음 행동이 다음 회차로 이어진다.
- 스터디 종료 후에도 결과 글과 회차 기록을 조회할 수 있다.

### 4.2 MVP 비목표

- 공개 커뮤니티·회원 모집 플랫폼·멀티테넌트 SaaS
- 실시간 채팅, 음성·영상회의, 실시간 공동편집
- AI 요약·추천·자동 커리큘럼
- 결제, 벌금, 포인트, 랭킹, 상세 출석 평가
- 정교한 업무관리: 의존성, 스토리 포인트, 속도 차트
- 대용량 첨부·동영상 자체 호스팅 (예외: 지식 글의 HTML 파일 1개, D-30)
- Discord·캘린더 자동 동기화와 자동 알림 (단, 로그인 시 Discord 서버 멤버·역할 확인은 포함)
- 개인 학습 항목·할 일·막힘 표시·미완료 이월 (D-03)
- 스터디별 비공개 권한 (D-06)
- 자체 회원가입·초대·가입 승인 (D-04)

## 5. 사용자와 권한

### 5.1 역할

- **커뮤니티 멤버:** 지정된 Discord 서버의 멤버. 모든 지식·스터디를 읽고, 지식 글·댓글을 작성한다.
- **스터디 멤버:** 스터디에 연결된 Discord 역할을 가진 커뮤니티 멤버 (D-23). 스터디 정보·회차·모임 기록을 생성·편집한다 (D-07, D-24).
- **운영자:** Discord 역할로 지정된다 (D-08). 카테고리 정리(이름 변경·보관)와 콘텐츠 숨김을 관리한다.

### 5.2 접근·변경 규칙

- 비로그인 사용자와 Discord 서버 비멤버는 내부 콘텐츠를 읽거나 변경할 수 없다.
- 커뮤니티 멤버는 모든 지식과 스터디를 읽는다 (D-06).
- 회차와 공동 모임 기록은 해당 스터디 멤버 누구나 생성·편집한다. 마지막 수정자와 수정 시각을 표시한다.
- 지식 글·댓글은 작성자만 수정·삭제한다 (D-19). 회차 공동 기록과 달리 공동 편집하지 않는다.
- 운영자는 운영상 콘텐츠를 숨길 수 있으나 타인 글의 저자로 변경하지 않는다.
- Discord 서버를 떠나면 접근만 막히고 글·작성자 표시는 그대로 둔다. 사이트 탈퇴(D-20)와 구분한다.
- 접근 제어는 화면뿐 아니라 서버의 개별 조회·변경 요청에도 적용한다.

### 5.3 Discord 연동 방식 — 제안

- Discord OAuth2 로그인 시 `identify`와 `guilds.members.read` 범위로 지정 서버의 멤버 여부와 역할을 조회한다. 별도 봇 없이 가능한 방식을 우선 검토한다.
- 사이트 설정에 서버 ID와 "운영자 역할 ID"를 둔다. 진행자 역할은 쓰지 않는다 (D-09).
- 역할·멤버 상태는 **로그인(또는 세션 갱신) 시점에 반영**한다. 실시간 동기화가 아니므로 서버를 떠난 사람은 세션 만료 전까지 접근할 수 있다. 세션 유효 기간을 짧게 두어 완화한다.
- 정확한 OAuth 범위·한도는 기술 설계에서 Discord 공식 문서로 재확인한다.

### 5.4 권한 요약

| 동작 | 커뮤니티 멤버 | 스터디 멤버 | 운영자 |
|---|---|---|---|
| 지식·스터디 읽기 | O | O | O |
| 지식 글·댓글 작성 (본인 것만 수정·삭제) | O | O | O |
| 카테고리 추가 | O | O | O |
| 스터디 정보(목표·설명·공통 자료·참여 안내) 편집 | | O | O |
| 회차 생성·편집, 모임 기록 | | O | O |
| 스터디 만들기·Discord 역할 연결·종료·재개 | | | O |
| 카테고리 이름 변경·보관, 콘텐츠 숨김 | | | O |

스터디 멤버 여부는 Discord 역할로 정해진다 (D-23). 스터디 관리자 역할은 없다 (D-24).

## 6. 핵심 사용 흐름

### 6.1 독립적인 지식 공유

1. 멤버가 지식 메뉴에서 글을 작성한다.
2. 카테고리·태그를 선택한다.
3. 내용과 참고 링크를 등록한다. 스터디 연결은 선택이다.
4. 다른 멤버가 검색·필터로 글을 찾고 댓글로 질문한다.

### 6.2 주간 스터디 사이클

1. 운영자가 스터디를 만들고 Discord 역할을 연결한다. 멤버는 Discord에서 역할을 받으면 스터디 멤버가 된다. 목표·공통 자료는 멤버가 채운다.
2. 스터디 멤버 누구나 다음 회차의 공통 학습 범위, 목표, 모임 시각·장소 또는 회의 링크를 등록한다.
3. 멤버는 공통 범위를 확인하고 공부한다. 대화·실시간 질문은 Discord에서 한다.
4. 모임 전까지 결과 글을 회차에 연결해 남긴다. 궁금한 점은 Discord에서 나눈다.
5. 모임에서는 회차에 연결된 글과 지난 회차의 남은 질문을 보며 발표·토론한다.
6. 스터디 멤버(주로 서기)가 핵심 논의·남은 질문·다음 행동을 공동 기록에 남기고 회차를 종료한다.
7. "다음 행동"과 "남은 질문"은 다음 회차 화면에 이전 회차 기록으로 보여준다. 별도 이월 기능은 없다.

### 6.3 지식 축적

- 결과 글 작성 시 관련 스터디·회차를 미리 연결한다.
- 기존 글도 나중에 회차에 연결할 수 있다.
- 스터디 종료·회차 보관은 글 자체를 삭제하거나 복제하지 않는다.
- 관련 글은 지식 목록과 스터디 회차에서 동일한 원본을 보여준다.

## 7. 정보 구조와 화면

### 7.1 홈

우선순위대로 보여준다.

- 다음 모임: 내가 참여 중인 스터디의 일시와 회차
- 이번 회차의 공통 학습 범위
- 최근 공유된 지식

모임이 없을 때 정상적인 빈 상태를 표시한다. 할 일 생성이나 학습 시간 입력을 강제하지 않는다.

### 7.2 지식 목록·상세·작성

- 목록: 카테고리·태그 필터, 제목·본문 검색, 최신순, 본문 미리보기
- 상세: 본문, 작성자, 수정 시각, 참고 링크, 관련 스터디·회차, 댓글
- 작성: Markdown 편집·미리보기, 분류 선택, 브라우저 임시저장

### 7.3 스터디 목록·상세

- 목록: 내 스터디 → 참여할 수 있는 스터디(참여 안내) → 종료된 스터디. 이름, 목표, 멤버 수, 다음 모임
- 상세: 목표, 공통 자료, 멤버, 다음 모임, 현재 회차, 과거 회차
- 회차 상세: 학습 범위, 일정, 연결된 글, 모임 기록, 이전 회차의 남은 질문·다음 행동
- MVP에서는 단순 목록으로 구현하며 칸반과 캘린더는 후순위다.

## 8. 기능 요구사항과 수용 기준

### F-01. 멤버 접근 — P0

- Discord OAuth2로 로그인·로그아웃한다. 자체 회원가입은 없다.
- 로그인 시 지정 Discord 서버의 멤버 여부를 확인하고, 운영자 역할을 함께 읽는다.
- 처음 로그인하면 Discord 닉네임·아바타로 멤버 프로필을 자동 생성한다.
- **수용 기준:** 비로그인·서버 비멤버 계정은 직접 URL과 API 요청으로도 내부 콘텐츠를 읽거나 변경할 수 없다.
- **수용 기준:** Discord에서 역할을 바꾸면 다음 로그인(세션 갱신) 때 사이트 권한에 반영된다.

### F-02. 지식 분류 — P0

- 글 하나에는 카테고리 하나와 태그 여러 개를 설정한다.
- 커뮤니티 멤버 누구나 글 작성 화면에서 새 카테고리를 추가한다 (D-17). 하위 카테고리는 지원하지 않는다.
- 추가 시 기존 카테고리 목록을 보여주고, 대소문자·공백만 다른 이름은 중복으로 막는다.
- 이름 변경·보관은 운영자만 한다. 카테고리 병합은 운영 후 필요하면 검토한다.
- 오픈 시 "기타" 카테고리 하나만 기본 제공한다.
- 보관된 카테고리는 기존 글에서 유지하지만 새 글에 선택할 수 없다.
- **수용 기준:** 카테고리 이름 변경 후 기존 글의 연결이 유지되며, 분류 변경 때문에 글이 삭제되지 않는다.
- **수용 기준:** 이미 있는 이름(대소문자·공백 무시)으로는 새 카테고리를 만들 수 없다.

### F-03. 글 작성·수정·삭제 — P0

- 글 종류는 없다 (D-22). 모든 글이 같은 형태다.
- 필수: 제목, 본문, 카테고리. 선택: 태그, 참고 링크, 관련 스터디·회차.
- 글은 최대 하나의 회차에 연결한다.
- **수용 기준:** 연결 없이 개인 글을 작성할 수 있고, 회차 연결 글은 지식과 해당 회차 양쪽에서 동일한 글 ID로 조회된다.
- 작성자는 자신의 글을 삭제한다 (D-19). 삭제 전 확인을 받고, 삭제는 되돌릴 수 없다. 글에 달린 댓글과 회차 연결도 함께 사라진다.
- **수용 기준:** 타인의 글 변경·삭제는 거부된다. 저장 실패 시 작성 내용이 유지되며 성공으로 표시하지 않는다.
- **수용 기준:** 삭제한 글은 지식 목록·검색·회차 어디에서도 조회되지 않는다.

### F-04. 검색·댓글 — P0

- 제목·본문 검색과 카테고리·태그 필터를 함께 적용한다.
- 댓글은 단일 계층이며 알림이 없다. 긴 토론은 Discord에서 한다 (D-05).
- **수용 기준:** 검색 조건에 맞는 접근 가능한 글만 반환한다. 운영자가 숨긴 글은 일반 검색에 노출하지 않는다.
- **수용 기준:** 자신의 댓글만 수정·삭제할 수 있으며, 운영자의 숨김 처리는 작성자 변경 없이 적용한다.

### F-05. 스터디 생성·멤버십 — P0

- 운영자가 만든다. 필수: 이름, 목표, Discord 역할. 선택: 설명, 공통 자료, 기본 모임 주기, 참여 안내(어떻게 역할을 받는지, 예: Discord 채널 링크).
- 상태: 진행 중 / 종료. 회원 모집 상태는 MVP에서 제외한다.
- 멤버십은 Discord 역할로만 정해진다 (D-23). 사이트에는 참여·나가기·멤버 제외 기능이 없다. 비멤버에게는 참여 안내를 보여 준다.
- 역할 변경은 로그인, 하루 1번 재확인, "내 역할 새로고침" 버튼으로 반영된다.
- 종료·재개는 운영자가 한다 (D-24).
- **수용 기준:** 역할이 없으면 읽기만 가능하고, 역할을 받은 뒤 새로고침하면 해당 스터디의 정보·회차·모임 기록을 작성·편집할 수 있다. 역할을 잃으면 같은 방식으로 편집 권한이 사라진다 (이미 쓴 글·기록은 유지).
- **수용 기준:** 종료 시 회차 생성·편집은 막히고 과거 글·회차는 보존된다. 운영자는 재개할 수 있다.

### F-06. 회차·모임 관리 — P0

- 필수: 제목, 공통 학습 범위, 회차 목표.
- 선택: 학습 기간, 모임 일시, 장소·회의 링크, 공통 자료.
- 생성·편집: 해당 스터디 멤버 누구나 (D-07). 마지막 수정자·시각을 표시한다.
- 상태: 진행 중 / 종료. 별도 "준비 중" 상태는 공동 편집 결정에 따라 제외를 제안한다. 각 상태와 무관하게 일정은 변경 가능하다.
- 반복 회차 자동 생성은 제외하고 수동 생성을 지원한다.
- **수용 기준:** 회차 화면에서 학습 범위와 일정이 함께 보인다. 일정 변경은 기존 글 연결을 깨뜨리지 않는다.
- **수용 기준:** 종료 회차에도 연결된 글의 댓글은 가능하다. 스터디 멤버는 종료를 취소해 재개할 수 있다.

### ~~F-07. 개인 학습 항목~~ — 제외 (D-03)

운영 후 "누가 무엇을 맡았는지"를 사이트에서 봐야 한다는 요구가 확인되면 단순 체크리스트 형태로 재검토한다.

### F-08. 회차 글 연결 — P0

- 글 작성 시 또는 이후에 회차를 연결·해제한다. 외부 링크는 글의 참고 링크로 남긴다.
- 회차 연결은 해당 스터디 멤버가 자신의 글에만 할 수 있다 (D-15). 스터디를 나가도 기존 연결은 유지한다.
- 회차에는 연결된 글을 최신순으로 모아 보여준다.
- **수용 기준:** 글을 수정하면 지식 목록과 회차 양쪽에 같은 수정 내용이 보인다. 연결 해제는 원본 글을 삭제하지 않는다.
- **수용 기준:** 결과 글이 삭제되거나 숨겨지면 회차 목록에서 빠진다.

### F-09. 모임 기록 — P0

- 스터디 멤버 누구나 회차별 공동 기록을 작성·편집한다: 핵심 논의 / 남은 질문 / 다음 행동.
- 개인의 배운 점·어려웠던 점은 댓글로 남길 수 있다.
- 다음 회차 화면에 직전 회차의 "남은 질문·다음 행동"을 읽기 전용으로 보여준다. 이월 기능은 없다.
- **수용 기준:** 회차 종료는 개인 회고 작성 여부와 무관하게 가능하다.
- 동시 편집 (D-11): 편집 시작 시점의 버전으로 저장을 요청한다. 그 사이 다른 사람이 저장했다면 저장을 거부하고, 최신 내용과 내 입력을 함께 보여줘 직접 합치게 한다.
- **수용 기준:** 두 사람이 동시에 기록을 편집할 때 한쪽 내용이 경고 없이 사라지지 않는다. 충돌 시 내 입력은 화면에 유지된다.
- 회차 정보(학습 범위·일정) 편집에도 같은 방식을 적용한다.

### F-10. 임시저장·기본 사용성 — P0

- 작성 중 내용은 현재 브라우저에만 임시저장한다 (D-12). 서버 초안과 기기간 이어쓰기는 없다.
- 로그아웃 시 해당 계정의 로컬 임시저장 데이터를 제거한다. 공용 PC 사용 시 유실·노출 주의를 안내한다.
- Markdown 미리보기, 서버 검증 오류, 저장 중·실패 상태를 제공한다.
- **수용 기준:** 저장 오류가 나도 입력 내용을 지우지 않는다. 재시도 중 중복 클릭으로 글·댓글이 중복 생성되지 않는다.
- **수용 기준:** 모바일에서 목록 조회·글 작성·댓글·상태 변경을 수행할 수 있다.

### F-11. 탈퇴 — P0

- 멤버는 사이트에서 직접 탈퇴한다 (D-20). 탈퇴 전, 글을 지우려면 먼저 직접 삭제해야 한다는 안내와 확인을 받는다.
- 탈퇴 시 프로필(닉네임·아바타)과 Discord 계정 연결을 지우고, 남은 글·댓글·공동 기록의 작성자는 "탈퇴한 멤버"로 표시한다.
- 같은 Discord 계정으로 다시 로그인하면 새 프로필이 만들어지며, 탈퇴 전 글과 다시 연결되지 않는다.
- **수용 기준:** 탈퇴 후 어떤 화면·API 응답에도 탈퇴자의 닉네임·아바타·Discord ID가 나타나지 않는다.
- **수용 기준:** 탈퇴 후에도 그 사람이 남긴 글과 회차 기록은 조회되고, 연결 관계가 깨지지 않는다.

## 9. 개념 데이터 모델

이 절은 제품 관계를 설명하며 DB 스키마 확정안이 아니다.

- **Member:** Discord 사용자 ID·닉네임·아바타, 마지막 확인된 서버 멤버 여부·역할, 탈퇴 여부 (탈퇴 시 식별 정보 제거)
- **Category / Tag:** 지식 분류
- **Post:** 제목, 본문, 카테고리·태그, 작성자, 선택적 회차 연결
- **Comment:** 글의 댓글 또는 회차의 토론·개인 회고
- **Study:** 목표, 공통 자료, 참여 안내, 연결된 Discord 역할, 진행 상태
- **StudyMembership:** Discord 역할에서 계산한 스터디와 멤버의 관계
- **Session(회차):** 학습 범위, 기간, 모임 정보, 상태, 공동 기록, 마지막 수정자, 버전(충돌 감지용)
- ~~LearningItem~~: 제외 (D-03)

핵심 관계:

- 스터디 하나는 여러 회차를 갖는다.
- 회차 하나는 여러 연결 글을 갖는다. 글은 최대 하나의 회차에 연결된다.
- 지식 글은 스터디·회차 없이 존재할 수 있다.
- 스터디 멤버십(사이트에서 관리)과 커뮤니티 접근 권한(Discord에서 관리)은 별개다.

## 10. 운영·비기능 요구사항

- **비용:** 도메인 포함 월 1만원 이하 (D-14). 무료 티어를 우선 검토하되, 백업·운영 편의를 위한 소액 지출은 허용한다. 비용은 도메인·호스팅·DB·백업 항목별로 추정해 기술 설계에 적는다.
- **기술 선택:** 1인 + AI로 만들고 운영하므로 (D-13) **운영 부담이 적은 관리형 서비스**를 우선한다. 이전 대화의 React + Vite, Cloudflare Workers + D1은 후보 중 하나다. Discord OAuth 구현 편의, 백업·복구 용이성, 동시 편집 버전 검사 구현 난이도를 기준으로 비교한다. 최신 한도와 요금은 기술 설계 시 공식 자료로 재확인한다.
- **시간:** 초기 일정 표시 기준은 KST로 제안한다. 저장 시각과 표시 시각을 구분하며 타임존을 명시한다.
- **보안:** 서버 접근 제어, Markdown 출력 안전 처리, 안전한 링크 프로토콜 제한, 비밀정보 서버 보관을 요구한다.
- **데이터 보존:** 글·댓글 삭제는 영구 삭제다 (D-19). 단, 백업에는 보존 기간 동안 남을 수 있음을 개인정보 안내에 적는다. 탈퇴는 식별 정보만 지우고 콘텐츠는 남긴다 (D-20). 수집 항목은 Discord ID·닉네임·아바타로 최소화한다.
- **백업:** 출시 전에 데이터 내보내기 및 복구 방법을 정하고 실제 복구를 시험한다. 실행 주기와 보존 기간은 기술 설계에서 확정한다.
- **오류 처리:** 실패한 작업은 성공으로 보이지 않아야 하고 작성 내용은 보존한다.
- **UI:** 모바일 대응, 키보드 기본 조작, 명확한 빈 상태, 비동기 처리 시 불필요한 레이아웃 이동 방지를 요구한다.
- **읽기 성능:** 예상 인원과 데이터 규모를 정한 뒤 목록·검색 응답 목표를 정한다. 확인되지 않은 부하 수치를 성능 보장으로 제시하지 않는다.

## 11. 출시 수용 시나리오

다음은 실제 구현 후 확인할 기준이며, 현재 통과 증거가 아니다.

1. 멤버가 스터디 연결 없이 지식 글을 작성하고 다른 멤버가 검색·댓글을 남긴다.
2. Discord 서버 멤버가 처음 로그인하면 프로필이 생기고, 비멤버는 차단된다.
3. 운영자가 스터디를 만들고 역할을 연결하면, 그 역할을 가진 멤버 중 한 명이 회차를 생성한다.
4. 멤버가 모임 전 결과 글을 남기고, 글이 지식 목록과 회차 모두에 나타난다.
5. 모임 후 공동 기록(핵심 논의·남은 질문·다음 행동)을 남긴다.
6. 다음 회차 화면에 직전 회차의 남은 질문·다음 행동이 보인다.
7. 스터디를 종료해도 과거 회차와 결과 글을 조회할 수 있다.
8. 권한 없는 계정의 직접 읽기·수정 요청이 차단된다. Discord 역할 변경이 재로그인 후 반영된다.
9. 글 저장 실패·중복 클릭·결과 글 삭제 후에도 입력과 연결 상태가 일관된다.
10. 모바일에서 핵심 흐름을 완료한다.
11. 백업 데이터를 복구하고 글·멤버십·회차 연결을 확인한다.
12. 멤버가 탈퇴하면 남은 글·기록의 작성자가 "탈퇴한 멤버"로 바뀐다.
13. 멤버가 새 카테고리를 추가하고, 같은 이름의 중복 생성은 막힌다.

## 12. 제품 검증과 성공 지표 — 제안

커뮤니티 전체에 오픈한 뒤 **8주 후 회고**로 아래 가설을 검증한다 (D-16). 회고 시 스터디별 멤버와 스터디에 속하지 않은 멤버 몇 명을 짧게 인터뷰한다.

**계속 운영 판단 기준 (D-18):**

1. 진행 중인 스터디의 70% 이상이 매 회차 모임 기록을 남긴다.
2. 스터디와 연결되지 않은 지식 글이 8주 평균 주 2개 이상 올라온다.

둘 다 미달이면 인터뷰로 원인을 확인한 뒤 범위를 줄이거나 운영 방식을 바꾼다. 아래 가설은 원인 파악용이다.

- 멤버가 별도 안내 없이 이번 학습 범위와 다음 모임을 찾을 수 있는가?
- 모임 전 결과 글이 사이트에 남고 모임에서 실제로 활용되는가?
- 과거 결과 글을 제목을 정확히 몰라도 분류·검색으로 다시 찾을 수 있는가?
- 일반 지식 공유가 스터디 등록 없이도 일어나는가?
- 기록과 상태 입력이 학습보다 부담스럽지 않은가?

보조 관찰 항목은 회차당 연결 글 수, 남은 질문이 다음 회차에서 다뤄지는지, 재검색 사례, 기록 담당자의 입력 부담이다. 어떤 수치도 사용자 평가·랭킹으로 사용하지 않는다.

## 13. 단계별 범위

### 출시 준비 (오픈 전 필수, D-16)

- 운영자 역할 지정 (카테고리는 멤버가 추가하므로 "기타"만 준비, D-17)
- 사이트 사용 안내 글 1개 (Discord 공지에 링크)
- 백업·복구 리허설 1회

### 마일스톤 제안 (D-13: 기한 대신 순서)

1. **M1 지식 공간:** Discord 로그인 + 지식 글·카테고리·검색·댓글·삭제·탈퇴. 이것만으로도 오픈 가능한 최소 단위.
2. **M2 스터디 공간:** 스터디·회차·글 연결·모임 기록·동시 편집 충돌 감지.
3. **M3 출시 준비:** 모바일 점검, 백업 복구 리허설, 안내 글 → 전체 오픈 → 8주 회고.

### MVP

Discord 로그인·서버 멤버/역할 확인, 지식 글·분류·검색·댓글, 스터디·회차(공동 편집), 회차 글 연결, 모임 기록, 본인 삭제·탈퇴, 임시저장과 기본 백업.

### 운영 후 검토

Discord 알림(새 회차 웹훅), 회차 템플릿·반복 생성, 즐겨찾기, 발표 순서, 가벼운 출석 체크, 개인 학습 체크리스트, 캘린더·칸반 보기, 파일 첨부.

### 필요가 확인될 때만 검토

공개 글, 스터디별 비공개, 다중 커뮤니티, 실시간 기능, AI 기능, 상세 통계.
